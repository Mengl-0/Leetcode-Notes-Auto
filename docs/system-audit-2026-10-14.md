## 二、发现的问题（按严重程度排序）

### 🔴 P0 — 明显的逻辑 bug，会导致功能错误

#### 问题 1：`auto_sync` 图片重复上传，浪费 OSS 流量
**位置**：`scripts/auto_sync.py` + `scripts/upload_img.py`

当前流程：
1. `batch_upload_assets()` 把 `assets/` 下所有图片上传到 OSS，**但没有把 url 写回 md**
2. `scan_all_md_replace()` 又扫描所有 md，对每个本地图片**再次上传**

虽然 OSS 端有内容哈希去重（`_build_remote_key` 用 sha1 前 8 位），不会产生重复文件，但**每张图会发两次 HTTP PUT 请求**，首次同步时白白浪费时间和 OSS 外网流出流量。

**能解决什么问题**：减少 50% 的图片上传请求，同步速度提升。
**什么问题依旧存在**：assets 目录的本地图片不会被自动清理（仍需手动删）。

---

#### 问题 2：AI 每日总结写入时日期标签错误
**位置**：`scripts/ai_assist.py:83`

```python
f.write(f"\n\n## 🤖 AI 总结（{today_str()}）\n\n{result}\n")
```

如果用户在 10 月 14 日对 10 月 10 日的历史笔记生成总结，写入的标题会写 `AI 总结（2026-10-14）`，而不是该笔记对应的日期 `2026-10-10`。

**能解决什么问题**：避免历史笔记被错误标注总结日期。
**什么问题依旧存在**：无。

---

#### 问题 3：`_get` 配置读取对空字符串处理不一致
**位置**：`config/settings.py:107`

```python
return os.getenv(key) or _LOCAL.get(key) or default
```

如果用户在 `secret.env` 里把某个值留空（如 `OSS_PREFIX=`），`_LOCAL.get(key)` 返回空字符串 `""`，会被 `or` 跳过，最终返回 default。这意味着**用户无法主动设置一个空值来覆盖默认值**（例如想让 OSS_PREFIX 留空，结果会回退到默认的 `img/`）。

**能解决什么问题**：让配置文件能精确控制空值。
**什么问题依旧存在**：环境变量设为空字符串仍会被跳过（这是 os.getenv 的固有行为，影响小）。

---

### 🟡 P1 — 健壮性 / 体验问题，不影响主流程但会踩坑

#### 问题 4：主菜单每次都用 subprocess 重启 Python 解释器
**位置**：`main.py:60`

```python
result = subprocess.run([sys.executable, str(script)])
```

每选一个菜单项，都要：
- 重新启动一个 Python 进程
- 重新 import 所有模块
- 重新读 `secret.env`
- 重新初始化日志 handler

启动慢（尤其在 Windows + 杀毒软件环境下），且无法在菜单间共享状态（例如刚建完索引，立刻问答还要重新加载）。

**能解决什么问题**：菜单切换速度提升 3~5 倍，RAG 问答时索引不用重新加载。
**什么问题依旧存在**：代码结构需要重构（scripts 不能直接 import，因为有 `if __name__ == "__main__"` 块）。

---

#### 问题 5：DeepSeek 调用无重试、无流式输出
**位置**：`core/ai_helper.py`

- 网络超时 / HTTP 500 直接返回 None，用户需要手动重新跑
- 长回答（如题解分析）一次性返回，用户等待期间没有任何进度提示

**能解决什么问题**：网络抖动时自动重试；长回答逐字输出，体验更好。
**什么问题依旧存在**：DeepSeek 服务端故障仍需用户手动重试。

---

#### 问题 6：RAG 索引无增量更新
**位置**：`core/rag.py`

`build_index()` 每次都扫描全部笔记、重新计算全部 IDF、重新向量化所有 chunk。当前只有 1 篇题解感受不到，但笔记超过 50 篇后，每次建索引都会明显变慢。

**能解决什么问题**：新增 1 篇笔记时，只向量化新 chunk，不重建全索引。
**什么问题依旧存在**：修改旧笔记仍需重建该笔记对应的 chunk；IDF 权重全局变化时仍需全量重建。

---

#### 问题 7：Git 推送失败时无自动 pull --rebase
**位置**：`core/git_auto.py:126-134`

push 失败时只打印提示「远程有新提交需先 pull」，用户要手动切到终端执行 `git pull --rebase` 再回来重新同步。

**能解决什么问题**：远程有冲突时自动 pull --rebase 再重试 push，减少手动操作。
**什么问题依旧存在**：真有代码冲突时仍需用户手动解决 merge。

---

#### 问题 8：Windows GBK 终端下 emoji 全部显示为 `?`
**位置**：`config/settings.py:27-32` + `main.py:16-21`

当前方案是 `errors="replace"`，emoji 降级为 `?`。功能不崩，但视觉体验差（菜单里全是 `?` 符号）。

**能解决什么问题**：让 Windows 终端也能正常显示 emoji（或统一改用纯文本符号）。
**什么问题依旧存在**：旧版 Windows 7 / 无 Unicode 终端环境仍无法显示。

---

#### 问题 9：OSS 上传失败后本地图片永久堆积
**位置**：`scripts/upload_img.py`

`assets/` 目录的图片上传成功后不会被删除或归档，失败的图片也会一直留在那里，下次同步会反复重试。长期使用后 assets 目录会膨胀。

**能解决什么问题**：成功上传的图片自动移到 `assets/uploaded/` 子目录，失败的留在原地，目录不混乱。
**什么问题依旧存在**：失败的图片仍需用户手动排查网络后重试。

---

### 🟢 P2 — 代码质量 / 可维护性问题

#### 问题 10：返回值类型不统一
- `ai_helper.chat()` 失败返回 `None`，成功返回 `str`
- `rag.build_index()` 失败返回 `([], False)`，成功返回 `(chunks, True)`
- `oss_upload.upload_file()` 失败返回 `None`，成功返回 `url`
- `notes_io.find_problem_note()` 找不到返回 `None`，找到返回路径字符串

调用方需要分别用 `if not result` / `if result is None` / `if chunks` 判断，容易写错。

**能解决什么问题**：统一返回 None（失败）/ 非 None（成功），减少判断分支。
**什么问题依旧存在**：历史调用点需要逐个改。

---

#### 问题 11：`settings.py` 模块导入时自动执行 `init_dir()`
**位置**：`config/settings.py:289`

任何 `from config.settings import xxx` 都会自动创建 5 个目录。在单元测试、CI 环境中这是副作用，可能污染测试环境。

**能解决什么问题**：目录创建改为显式调用（main.py 启动时调一次）。
**什么问题依旧存在**：老用户升级时如果没改 main.py 会报目录不存在。

---

#### 问题 12：缺少类型注解
除了少量函数有 `-> str` / `-> bool`，大部分函数没有类型提示。IDE 跳转和静态检查（mypy）帮助有限。

**能解决什么问题**：IDE 自动补全更准，重构更安全。
**什么问题依旧存在**：第三方库（oss2）本身类型不完整。

## 四、修改建议（按优先级）

### 🥇 第一优先级：本周可做，立即提升体验

#### 建议 1：修复 auto_sync 图片重复上传
**改动位置**：`scripts/auto_sync.py`
**改动思路**：
- 调用 `batch_upload_assets()` 后，拿到返回的 `{本地路径: url}` 映射
- 把这个映射传给 `scan_all_md_replace()`，让它直接用已有 url，不再二次上传
- 改 `core/oss_upload.replace_img_in_md` 接受一个可选的 `url_cache` 参数

**能解决**：问题 1（重复上传）
**收益**：同步速度提升 50%，OSS 外网流量减半
**什么问题依旧存在**：assets 本地图片仍需手动清理（见建议 5）

---

#### 建议 2：修复 AI 总结日期标签 bug
**改动位置**：`scripts/ai_assist.py:83`
**改动**：把 `today_str()` 换成用户输入的 `date_str`（如果为空则用 today_str()）

**能解决**：问题 2
**收益**：历史笔记总结日期正确
**什么问题依旧存在**：无

---

#### 建议 3：主菜单改为进程内调用，不再 subprocess
**改动位置**：`main.py` + 各 `scripts/*.py`
**改动思路**：
- 把每个 script 的核心逻辑抽成 `run()` 函数
- main.py 直接 `from scripts.xxx import run` 调用
- 保留 `if __name__ == "__main__"` 块让脚本仍可单独跑

**能解决**：问题 4（启动慢）、问题 6（索引重复加载）
**收益**：菜单切换快 3~5 倍；RAG 问答时索引已在内存
**什么问题依旧存在**：首次启动仍要 import 全部模块；内存占用略增

#### 建议 5：上传成功的图片自动归档

#### 建议 6：Git push 失败时自动 pull --rebase

**能解决**：问题 7（远程冲突手动处理）
**收益**：日常同步几乎不用手动干预

## 五、当前数据状态的特别提醒

1. **RAG 知识库效果未验证**：当前只有 1 篇题解 + 1 篇空 daily，hash 向量的检索质量、IDF 权重是否合理，都需要至少 10~20 篇真实笔记才能评估。建议先刷 10 道题、建完索引，再测试 RAG 问答效果。

2. **每日笔记是空模板**：`2026-10-08.md` 的表格、收获、踩坑全是空的。AI 每日总结功能（菜单 6 → 2）对空笔记生成的总结会很空洞，建议先手动写几天笔记再用 AI 总结。

3. **DeepSeek / OSS 配置状态未知**：当前审计无法判断 `config/secret.env` 是否已填写。建议运行 `python main.py` 选菜单 8「配置体检」确认。

## 六、一句话总结

> 项目骨架和安全设计已经很扎实，**当前最大的瓶颈不是代码 bug，而是数据量太小、真实使用场景太少**。建议先按第一优先级修 3 个小 bug（图片重复上传、AI 日期标签、subprocess 启动慢），然后用 2 周时间真实刷题积累 10~20 篇笔记，再根据真实使用中遇到的问题迭代。
